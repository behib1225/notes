<small>LLM foundations (Ch 2)</small><br>Roughly how many English words is one token?	About <b>0.75</b>.	agentic-ai llm formula
<small>LLM foundations (Ch 2)</small><br>Total input tokens for an n-step loop with prefix P and d tokens added per step: T<sub>in</sub> = ___	<div class="eq">T<sub>in</sub> = nP + d·n(n−1)/2</div>The history term is <b>quadratic in steps</b>, which is why long agents need compaction, sub-agents and caching.	agentic-ai llm formula
<small>LLM foundations (Ch 2)</small><br>What is context rot?	Recall and reasoning degrade as context grows; information buried in long contexts is attended to less reliably. Aim for the <b>smallest set of high-signal tokens</b>.	agentic-ai llm
<small>LLM foundations (Ch 2)</small><br>How does prompt (prefix) caching work?	The provider stores the KV attention states of a repeated prompt prefix; a request starting with the identical prefix skips recomputing it. Cached input is cheaper and faster.<br><br><i>More:</i> Anthropic uses explicit cache breakpoints; providers often charge a small premium to write to the cache.	agentic-ai llm
<small>LLM foundations (Ch 2)</small><br>What design rule follows from prefix caching?	<b>Stable prefix, append-only history.</b> System prompt and tools first; nothing volatile at the top; never edit or reorder earlier messages, since any change invalidates everything after it.	agentic-ai llm
<small>LLM foundations (Ch 2)</small><br>A high-volume agent puts “Current time: 2026-10-27T14:03:11Z” on line 1 of the system prompt. Problem and fix?	It changes every request, so the cache never hits and you pay full price for the whole prefix. Move volatile values to the end (latest user message) or round them (date only).	agentic-ai llm scenario
<small>LLM foundations (Ch 2)</small><br>What does temperature do, and what does “temperature 0” mean?	It divides logits before softmax: lower = sharper, more greedy. As T → 0 sampling approaches argmax; APIs implement T = 0 as <b>greedy decoding</b> (dividing by 0 is undefined).	agentic-ai llm
<small>LLM foundations (Ch 2)</small><br>What does top-p (nucleus) sampling keep?	The smallest set of most-probable tokens whose cumulative probability reaches p; it renormalises and samples from them.<br><br><i>More:</i> Reasoning models often restrict or ignore temperature and top-p.	agentic-ai llm
<small>LLM foundations (Ch 2)</small><br>Why doesn’t temperature 0 give identical outputs in production?	Batched inference changes floating-point reduction order with batch composition, so near-tied logits can flip; one changed token alters everything after it, and divergence compounds over long trajectories.	agentic-ai llm
<small>LLM foundations (Ch 2)</small><br>A teammate: “Our eval is flaky; set temperature 0.” Your reply?	That reduces variance, not removes it. Run each case several times (k ≈ 5), report mean with confidence intervals or pass^k, track variance as a metric, and make tools idempotent.<br><br><i>More:</i> Reasoning models may not even expose temperature.	agentic-ai llm scenario
<small>LLM foundations (Ch 2)</small><br>What are reasoning models, and how are they controlled?	Models that produce a hidden or summarised chain of thought before answering, trading latency and tokens for accuracy; trained largely with RL on verifiable rewards. Controls: an <b>effort level</b> or a <b>thinking-token budget</b>.	agentic-ai llm
<small>LLM foundations (Ch 2)</small><br>What is interleaved thinking, and how should you allocate reasoning effort?	The model reasons <b>between tool calls</b>, reading each result before the next step. Use high effort for planning and hard decisions; low effort or a small model for routine steps.	agentic-ai llm
<small>LLM foundations (Ch 2)</small><br>Order the five steps of the tool-calling cycle.	Send definitions (name, description, JSON Schema) → model emits a tool-call block and stops with <code>tool_use</code> → <b>your code</b> executes it → append a tool result linked by ID → call again until no tool call.<br><br><i>More:</i> Exception: hosted tools (e.g. provider-run web search) are executed by the provider.	agentic-ai llm
<small>LLM foundations (Ch 2)</small><br>What does the model physically output when it “calls a tool”?	Ordinary tokens in a trained format that the API parses into a structured block (name + JSON arguments). Nothing executes until your code runs it and returns the result.	agentic-ai llm
<small>LLM foundations (Ch 2)</small><br>What are parallel tool calls?	Several tool calls in one model turn; execute them (ideally concurrently) and return all results together in the next message.	agentic-ai llm
<small>LLM foundations (Ch 2)</small><br>How does constrained decoding guarantee schema-valid output?	At each step the sampler masks tokens that would violate the JSON Schema or grammar, so output always parses. E.g. Anthropic <code>strict: true</code> tools; OpenAI Structured Outputs.	agentic-ai llm
<small>LLM foundations (Ch 2)</small><br>Two caveats of structured outputs?	Schema-valid can still be <b>wrong</b> (valid JSON, wrong order ID). Tight constraints can <b>hurt reasoning</b>: let the model think in free text first, then emit the structure.	agentic-ai llm
<small>LLM foundations (Ch 2)</small><br>Is the system/user instruction hierarchy a security boundary?	No. It is a trained, soft preference (system over user, tool results as data). Prompt injection needs <b>architectural</b> defences.	agentic-ai llm
<small>LLM foundations (Ch 2)</small><br>Prompt structure: what order, and how do you handle untrusted input?	Role and background → task → constraints → output format → examples. Delimit sections and untrusted data with XML tags so the model and your code can tell data from instructions.	agentic-ai llm
<small>LLM foundations (Ch 2)</small><br>Three phrasing habits that improve prompts?	Put long documents first and the question last; explain <i>why</i> a rule exists; say what to do rather than what not to do.<br><br><i>More:</i> Few-shot: a handful of diverse, canonical examples, varied so the model doesn’t copy surface features.	agentic-ai llm
<small>LLM foundations (Ch 2)</small><br>How should you prompt reasoning vs non-reasoning models?	Non-reasoning: ask for step-by-step thinking before the answer. Reasoning models: state goal, constraints and success criteria instead of scripting each step.	agentic-ai llm
<small>LLM foundations (Ch 2)</small><br>What does “prompts are code” mean?	Version prompts, change one thing at a time, re-run the eval suite on every change. A prompt tuned for one model isn’t automatically right for another.	agentic-ai llm
<small>LLM foundations (Ch 2)</small><br>Context engineering vs prompt engineering?	Context engineering decides <b>what</b> the model sees; prompt engineering decides <b>how it is phrased</b>.	agentic-ai llm

Cost without caching, and with cached input at 10% price?	≈160K input + 2.4K output → <b>≈$0.52</b>. <small>Architectures and patterns (Ch 3)</small><br>Workflow vs agent?	A <b>workflow</b> runs LLMs and tools along code paths you define in advance. An <b>agent</b> lets the LLM direct its own process and tool use in a loop.<br><br><i>More:</i> Anthropic’s guidance: the right answer may be not building an agentic system at all.	agentic-ai patterns
<small>Architectures and patterns (Ch 3)</small><br>The five rungs of the autonomy ladder, and the rule for climbing?	Single call → augmented LLM → workflow → single agent → multi-agent. Climb only when the rung below <b>fails on your eval</b>; each rung costs predictability, latency, money and debuggability.	agentic-ai patterns
<small>Architectures and patterns (Ch 3)</small><br>Name the five workflow patterns.	Prompt chaining, routing, parallelization, orchestrator-workers, evaluator-optimizer.	agentic-ai patterns
<small>Architectures and patterns (Ch 3)</small><br>Prompt chaining?	A fixed sequence where each call consumes the previous output, with optional programmatic “gates”. For tasks that split into fixed stages (outline → check → write → translate).	agentic-ai patterns
<small>Architectures and patterns (Ch 3)</small><br>Routing?	A classifier sends each input to a specialised prompt, tool set or model. For distinct input categories (support triage; easy questions to a small model).	agentic-ai patterns
<small>Architectures and patterns (Ch 3)</small><br>Parallelization: sectioning vs voting?	<b>Sectioning</b>: independent subtasks at once (guardrail check alongside the answer). <b>Voting</b>: same task several times, results aggregated (three reviewers vote).	agentic-ai patterns
<small>Architectures and patterns (Ch 3)</small><br>Orchestrator-workers?	A central LLM decomposes the task <b>at run time</b>, delegates to workers and synthesises. For subtasks you can’t predict (unknown set of files; multi-source research).	agentic-ai patterns
<small>Architectures and patterns (Ch 3)</small><br>Evaluator-optimizer?	One LLM generates, another critiques against criteria, loop until pass. For clear criteria where iteration measurably helps (translation, rubric writing).	agentic-ai patterns
<small>Architectures and patterns (Ch 3)</small><br>What is ReAct?	Yao et al., 2022: interleaved Thought / Action / Observation in one trajectory. Native tool calling with interleaved thinking is essentially ReAct built into the model and API.	agentic-ai patterns
<small>Architectures and patterns (Ch 3)</small><br>Plan-and-execute: when better than ReAct, when worse?	Writes a plan first, then executes (often with a cheaper model). <b>Better</b>: a 40-step migration whose plan a human approves before writes. <b>Worse</b>: debugging, where each observation changes the next step.	agentic-ai patterns
<small>Architectures and patterns (Ch 3)</small><br>Reflexion: what is it, and when does it work best?	Shinn et al., 2023: after a failed attempt the agent writes a verbal lesson to memory and retries. Best with an <b>external signal</b> such as a failing test.	agentic-ai patterns
<small>Architectures and patterns (Ch 3)</small><br>When is tree search (Tree-of-Thoughts, LATS) right in production?	Rarely: branching and backtracking are expensive. Use it only when a <b>cheap verifier</b> exists.	agentic-ai patterns
<small>Architectures and patterns (Ch 3)</small><br>Do modern agents need elaborate explicit planners?	Often not. Today’s reasoning models plan and recover internally, so many teams use a <b>simple loop with strong tools and good context</b>, adding structure only where traces show failures.	agentic-ai patterns handbook-advice

<small>Architectures and patterns (Ch 3)</small><br>Why do subagents reduce context rot even though total tokens rise?	Each explores in a fresh context and returns a condensed result, so the lead’s context stays short and high-signal for each decision.	agentic-ai patterns

<small>The agent loop and tools (Ch 4)</small><br>How does the handbook’s loop guard work, and why reset it?	Key each call by (name, sorted-JSON args); block the <b>third identical call</b> with an error. Reset after a successful write, because state changed and re-checks are now legitimate.	agentic-ai loop
<small>The agent loop and tools (Ch 4)</small><br>Why return tool errors as observations instead of raising?	An actionable error lets the model self-correct; an exception kills a long, expensive trajectory. Log the stack trace separately.	agentic-ai loop

Each <code>tool_use</code> must be answered by a matching <code>tool_result</code> (same ID) in the <b>next</b> user message. Splitting breaks the pairing and discourages future parallel calls.	agentic-ai loop
<small>The agent loop and tools (Ch 4)</small><br>Why cap tool output size?	To protect the context window and cost. Truncate at a sensible boundary and tell the model how to get more.	agentic-ai loop

<small>Evaluating agents (Ch 8)</small><br>pass@k and pass^k: definitions and formulas (independent attempts)?	<b>pass@k</b> = P(≥1 of k succeeds) = 1 − (1−p)<sup>k</sup>. <b>pass^k</b> = P(all k succeed) = p<sup>k</sup>. pass^k (from τ-bench) fits customer-facing agents, where consistency matters.	agentic-ai evals formula
<small>Evaluating agents (Ch 8)</small><br>p = 0.9 per attempt: pass@8 and pass^8? p = 0.95: pass^5?	pass@8 ≈ 1.0, pass^8 ≈ <b>0.43</b>; pass^5 ≈ <b>0.77</b>. A bank’s agent should be judged on pass^k.	agentic-ai evals formula
<small>Evaluating agents (Ch 8)</small><br>Unbiased pass@k estimator from n runs with c successes?	<div class="eq">pass@k = 1 − C(n−c, k) / C(n, k)</div>Compute per task, then average (Chen et al., 2021).	agentic-ai evals formula
<small>Evaluating agents (Ch 8)</small><br>Estimator for pass^k from n runs with c successes?	<div class="eq">pass^k = C(c, k) / C(n, k)</div>Probability that k runs drawn without replacement all succeed; average over tasks.	agentic-ai evals formula

<small>Training models for agents (Ch 9)</small><br>PPO clipped objective (maximised)?	<div class="eq">L = E[ min( ρ<sub>t</sub>A<sub>t</sub>, clip(ρ<sub>t</sub>, 1−ε, 1+ε)A<sub>t</sub> ) ]</div>ρ<sub>t</sub> = π<sub>θ</sub>(a<sub>t</sub>|s<sub>t</sub>) / π<sub>old</sub>(a<sub>t</sub>|s<sub>t</sub>). <small>Training models for agents (Ch 9)</small><br>DPO: what it does, strengths, weakness?	Raises the preferred response’s likelihood relative to the rejected one, versus a frozen reference; no reward model or RL loop. Stable and cheap, good for tone and safety; offline, so weaker for multi-step skills learned from own mistakes.	agentic-ai training
<small>Training models for agents (Ch 9)</small><br>DPO or GRPO?	<b>DPO</b> for preference pairs on hard-to-verify qualities (tone, helpfulness). <b>GRPO</b> when a programmatic verifier exists and the skill is multi-step.	agentic-ai training
<small>Training models for agents (Ch 9)</small><br>What is RLVR, and why is it effective?	RL where a <b>program</b> computes the reward (tests pass, answer matches, final state correct). Harder to hack than learned reward models and it scales; behind o1 and DeepSeek-R1.	agentic-ai training
<small>Training models for agents (Ch 9)</small><br>GRPO advantage formula?	For a group of G completions per prompt:<div class="eq">A<sub>i</sub> = (r<sub>i</sub> − mean(r)) / std(r)</div>applied to every token of completion i in a PPO-style clipped objective, optionally with a KL penalty.<br><br><i>More:</i> Introduced in DeepSeekMath (2024). Implementations add a small ε to the std.	agentic-ai training formula
<small>Training models for agents (Ch 9)</small><br>Why is GRPO popular?	It drops the <b>value network</b>: the group mean is the baseline. Saves memory, avoids training a critic on long sequences, pairs well with verifiable rewards.	agentic-ai training
<small>Training models for agents (Ch 9)</small><br>All completions in a GRPO group get the same reward. Consequence?	std = 0 → all advantages 0: <b>no learning signal</b>, wasted compute. Fix with curricula keeping outcomes mixed, or DAPO’s dynamic sampling.	agentic-ai training
<small>Training models for agents (Ch 9)</small><br>What does Dr. GRPO change, and why?	Removes per-sequence <b>length normalisation</b> and <b>std scaling</b>, which bias training toward long wrong answers and toward very easy or very hard prompts.	agentic-ai training
<small>Training models for agents (Ch 9)</small><br>DAPO’s four additions?	Asymmetric clip-higher (keeps exploration), token-level loss averaging, dynamic sampling (drops identical-reward groups), overlong penalties.	agentic-ai training
<small>Training models for agents (Ch 9)</small><br>During GRPO training, wrong answers get longer and longer. Likely cause and fixes?	Length normalisation in the loss dilutes the penalty on long wrong answers. Use Dr. GRPO-style unnormalised loss or token-level averaging, and add an overlong penalty.	agentic-ai training scenario
<small>Training models for agents (Ch 9)</small><br>Early in GRPO training almost every group gets reward 0. What do you do?	Tasks are too hard: no signal. Warm-start with SFT, use a curriculum from easier tasks, give partial-credit rewards, and filter all-zero groups.	agentic-ai training scenario
