Why state a non-ML baseline in the framing step?	The model must beat it, it is the fallback when the model fails, and it can ship quickly to start collecting training data.	chapter-1_2 concept

Why do interviewers ask for p99 latency instead of the average?	In fan-out systems the page waits for the slowest backend call, so a backend’s tail latency becomes the user’s typical latency (Dean &amp; Barroso, “The Tail at Scale”).	chapter-3 concept
A request fans out to 20 independent backend calls. Each exceeds its p99 with probability 1%. What fraction of requests hit at least one slow call?	1 − 0.99²⁰ ≈ 18%.<br><br><i>With 100 calls it is ≈ 63%. Correlated slowness can make the real figure better or worse, so measure it.</i>	chapter-3 calc
What is a hedged request?	Sending a duplicate request after a short delay and using whichever response arrives first, to cut tail latency.	chapter-3 concept
Three estimation shortcuts: seconds per day, QPS per 1M requests/day, peak-to-average ratio.	1 day ≈ 86,400 s ≈ 10⁵ s; 1M requests/day ≈ 12 QPS; peak ≈ 2–5× average.	chapter-3 formula
300M requests/day. Average QPS, and peak QPS at 3× average?	3×10⁸ ÷ 86,400 ≈ 3,500 QPS average (≈ 3,000 with the 10⁵ shortcut); ≈ 10,000 QPS peak.	chapter-3 calc
Order from fastest to slowest: datacenter round trip, DRAM reference, cross-continent round trip, NVMe SSD 4 KB random read.	DRAM (~100 ns) &lt; SSD random read (~20–100 µs) &lt; datacenter round trip (~0.5 ms) &lt; US–Europe round trip (~70–100 ms).<br><br><i>Memorize ratios, not digits; long-distance round trips are bounded by the speed of light in fibre.</i>	chapter-3 concept
After a back-of-envelope estimate, what should you name for the interviewer?	The dominant factor. Ranking cost = requests × candidates × FLOPs per candidate, so the first lever is fewer candidates — the reason multi-stage ranking exists.	chapter-3 concept
100M user embeddings, 128 dimensions, float32. Storage? And in float16?	10⁸ × 128 × 4 B ≈ 51 GB; ≈ 26 GB in float16.	chapter-3 calc
Replication vs sharding.	Replication copies data to several machines for availability and read throughput. Sharding splits data across machines when it does not fit on one.	chapter-3 concept
During a network partition, does ML serving usually prefer consistency or availability?	Availability: a slightly stale feature value is better than a failed request.	chapter-3 concept
Why might you compute a feature in a daily batch job even though streaming is fresher?	Streaming is costlier and harder (backfills, late events, exactly-once). Use it only for features whose value decays quickly, such as transaction velocity.	chapter-3 concept
What does it mean for an operation to be idempotent?	Doing it twice has the same effect as doing it once, so clients can safely retry.	chapter-3 concept
What is graceful degradation in ML serving?	When a component fails, serve a worse but valid result — e.g., cached or popularity-based results when the ranker times out.	chapter-3 concept
Why is choosing the objective the most consequential design decision?	The model maximizes it relentlessly, including its loopholes: optimizing clicks yields clickbait; optimizing watch time can promote compulsive use.	chapter-4 concept
Typical multi-signal feed score.	score = w₁·P(click) + w₂·E[watch time] + w₃·P(like) − w₄·P(report), with weights tuned in online experiments.	chapter-4 formula
Pointwise vs pairwise vs listwise learning to rank.	Pointwise scores each item independently; pairwise learns which of two items is better (RankNet); listwise optimizes the whole list’s quality (ListNet, LambdaMART).	chapter-4 concept
When should you not use ML?	When a simple stable rule suffices (e.g., a legal rule), there are no labels, errors must be legally explainable, or maintenance costs exceed the value. Many systems are hybrid: rules for hard constraints, ML for the fuzzy middle.	chapter-4 concept
Define uplift (conditional average treatment effect).	τ(x) = P(Y=1 | x, treated) − P(Y=1 | x, not treated): the change in outcome caused by the action.	chapter-4 formula
Which of the four uplift segments should receive a coupon?	Only persuadables (buy only with the coupon). Not sure things (buy anyway), lost causes (never buy) or sleeping dogs (contact makes them leave).	chapter-4 concept
T-learner vs S-learner.	T-learner: one model on treated, one on control, subtract predictions. S-learner: one model with the treatment flag as a feature, predicted with the flag on and off.	chapter-4 concept
Why is a randomized pilot preferred for training uplift models?	Observational data confuses “whom we chose to treat” with “what the treatment does”; observational methods rely on the unverifiable no-unmeasured-confounders assumption.	chapter-4 concept
How do you evaluate an uplift model?	Qini or uplift curves on a randomized holdout: rank by predicted uplift and measure the incremental outcome from treating the top k versus a random k.	chapter-4 concept
A churn model (AUC 0.85) targets the top 5% with retention offers; a randomized test shows almost no effect. Why, and what instead?	It ranks churn risk, not the offer’s effect: many targets are lost causes or sleeping dogs. Run a randomized pilot, train an uplift model, target highest predicted uplift.	chapter-4 scenario
Main weakness of each label source: explicit, implicit, human annotation, delayed natural, weak/programmatic.	Explicit: sparse. Implicit: noisy and biased by what was shown. Human: expensive, labelers disagree. Delayed: training data is always old. Weak: noisy — validate against a gold set.	chapter-5 concept
Three mitigations for position bias in click labels.	Use position as a training feature and set it to a constant at serving; inverse propensity weighting; randomize a small traffic slice to estimate the bias.	chapter-5 concept
What is selection (exposure) bias and its standard mitigation?	You only get labels for items the current system chose to show. Reserve exploration traffic for random or uncertain items.	chapter-5 concept
What is a feedback loop in ML systems?	Today’s model decides tomorrow’s training data, which can amplify popularity and bias over time.	chapter-5 concept
What counts as a negative example for a click model?	An impression without a click. An item that was never shown is not a negative — the user had no chance to click it.	chapter-5 concept
What are hard negatives used for in retrieval training?	Items similar to the positive but not engaged with; they teach finer distinctions than random negatives.	chapter-5 concept
Probability correction after keeping negatives at rate w.	q = p / (p + (1 − p)/w), where p is the model output (He et al., 2014).	chapter-5 formula
Negatives were kept at 10% (w = 0.1). The model predicts p = 0.5. Calibrated probability?	q = 0.5 / (0.5 + 0.5/0.1) = 0.5 / 5.5 ≈ 0.091.	chapter-5 calc
Which metrics suit heavy class imbalance?	PR-AUC and operating-point metrics such as recall at fixed precision — not accuracy.	chapter-5 concept
How should you split data for a production model that evolves over time?	By time (train on the past, test on the future), by group (e.g., user) to measure generalization to new entities, and with a gap before the test period when labels are delayed.	chapter-5 concept

What is point-in-time correctness?	Each training example’s features use only data available strictly before that example’s timestamp. Feature-store point-in-time joins enforce it.	chapter-5 concept
A churn model has 0.97 AUC offline and is no better than random online. What do you check first?	Leakage — a suspiciously high offline AUC is itself a warning sign. Then training–serving skew.	chapter-5 scenario
Most common cause of silent model degradation, and the defense?	Unannounced upstream data changes (units, casing, dropped events). Automated validation of schema, ranges, null rates and distributions.	chapter-5 concept
What is reject inference in credit models?	Outcomes exist only for applicants the old policy approved, so the model cannot learn from rejected applicants (selection bias).	chapter-5 concept
What does UICX stand for?	User, Item, Context and Cross (interaction) features.	chapter-6 concept
How do you represent high-cardinality IDs such as user ID or zip code?	Learned embeddings or the hashing trick.	chapter-6 concept
Why is the hashing trick acceptable despite collisions?	With enough buckets frequent values rarely collide, and rare values carry little signal. You gain fixed memory, no vocabulary, and natural handling of unseen values.	chapter-6 concept
How do you handle heavy-tailed numeric features (counts, prices)?	Log transform or bucketize.	chapter-6 concept
How should missing values be represented?	An explicit missing indicator plus an imputed value — missingness is often informative.	chapter-6 concept
Batch, streaming and on-demand features: one example and freshness for each.	Batch: 30-day average watch time (hours–1 day). Streaming: clicks in the last 5 minutes (seconds). On-demand: user–restaurant distance now (instant).	chapter-6 concept
Three causes of training–serving skew.	Separate codebases computing a feature differently, different timing (end-of-day vs live values), different missing-value handling.	chapter-6 concept
Most reliable fix for training–serving skew.	Log the feature values used at serving and train on those logs (“log-and-wait”), with shared feature definitions.	chapter-6 concept
What four things does a feature store provide?	A shared registry of definitions, an offline store with point-in-time joins, a low-latency online store, and pipelines that materialize features online.	chapter-6 concept
Two roles of embeddings in ML systems.	Input features for downstream models, and keys for nearest-neighbour retrieval.	chapter-6 concept
A velocity feature is exact in training (SQL) but its serving counter (stream job) lags by 2 minutes. Consequence?	Serving undercounts during bursts — exactly when fraud spikes — so the model under-reacts. Train on logged served values and alert on stream lag.	chapter-6 scenario

When is GBDT preferred over a deep model?	Mostly tabular data with engineered features, small-to-medium datasets, need for interpretability and fast iteration, no GPU serving.	chapter-7 concept
When do deep models beat GBDT?	Huge data, very high-cardinality IDs needing embeddings, raw multimodal inputs, sequence features, multi-task objectives.	chapter-7 concept

Structure of DLRM.	Embedding tables for sparse features, MLPs for dense features, and explicit pairwise feature interactions.	chapter-7 concept
Two-tower vs cross-encoder: the trade-off.	Two-tower: user and item meet only in a dot product, so item vectors are precomputed for ANN retrieval over millions — less expressive. What bias do in-batch negatives cause, and how is it corrected?	Popular items appear as negatives more often, so they are over-penalized. The logQ correction subtracts each item’s log sampling probability from its logit (Yi et al., 2019).	chapter-7 concept
Loss for a p90 delivery-time prediction?	Quantile (pinball) loss with τ = 0.9.	chapter-7 concept
Loss family for training retrieval embeddings?	Softmax / sampled softmax / InfoNCE (contrastive).	chapter-7 concept
How does LambdaMART weight errors?	Each pairwise gradient is scaled by |ΔNDCG| from swapping the pair, so errors near the top count more; the gradients train boosted trees.	chapter-7 concept
What problem does MMoE address in multi-task ranking?	Negative transfer between conflicting tasks, by using task-specific gates over shared experts.	chapter-7 concept
Define calibration and name two post-hoc fixes.	Among examples predicted 0.3, about 30% are positive. Fixes: Platt scaling, isotonic regression (also temperature scaling). Measure with reliability diagrams and ECE.	chapter-7 concept
Four ways to make a model cheap enough to serve.	Distillation, quantization, pruning, and caching/precomputation (e.g., item embeddings offline).	chapter-7 concept
How does a new item get recommended before any interactions?	Content features (text/image embeddings, creator features) give it a meaningful embedding immediately; reserve exploration traffic for new items.	chapter-7 concept
How do you handle a brand-new user?	Use context (location, device, signup answers), popularity and quick exploration; update the user representation within the session.	chapter-7 concept
What is target attention (Deep Interest Network)?	The candidate item acts as the query attending over the user’s history, so the model focuses on the history relevant to that candidate.	chapter-7 concept
Precision and recall.	Precision = TP / (TP + FP). Recall = TP / (TP + FN).	chapter-8 formula
What does ROC-AUC measure?	The probability that a random positive is scored above a random negative.	chapter-8 concept
Why can ROC-AUC look good but be misleading at a 0.05% positive rate?	It is dominated by easy negatives: a tiny false-positive rate over millions of negatives still produces far more false positives than true positives. PR-AUC exposes this.	chapter-8 concept
What is normalized entropy (Facebook ads)?	Log loss divided by the entropy of the background CTR, making log loss comparable across base rates.	chapter-8 concept
When is MRR the right ranking metric?	When only the first relevant result matters (e.g., question answering). MRR = mean of 1 / rank of the first relevant item.	chapter-8 concept
DCG@K and NDCG@K.	DCG@K = Σᵢ (2^relᵢ − 1) / log₂(i + 1). NDCG@K = DCG@K / IDCG@K.	chapter-8 formula
Which items must IDCG be computed from?	All relevant items known for the query, including those the model failed to return; otherwise low recall goes unpunished.	chapter-8 concept
Model ranks two items with relevance [1, 3]; these are all relevant items. NDCG@2?	DCG = 1/1 + 7/log₂3 ≈ 5.42. IDCG (order [3, 1]) = 7 + 1/log₂3 ≈ 7.63. NDCG ≈ 0.71.	chapter-8 calc
Which offline metric fits each stage: retrieval, ranking, rare events, calibration?	Recall@K; NDCG or AUC; PR-AUC or operating-point metrics; log loss.	chapter-8 concept
A/B sample size per group (α = 0.05 two-sided, power 0.8).	n ≈ 16σ² / δ². For a per-user binary metric, σ² = p(1 − p).<br><br><i>16 ≈ 2 × (1.96 + 0.84)².</i>	chapter-8 formula
Per-user conversion is 10%. You need to detect a +0.5 percentage-point absolute lift. Users per group?	σ² = 0.1 × 0.9 = 0.09; n ≈ 16 × 0.09 / 0.005² ≈ 57,600.	chapter-8 calc
You need 300k users per group, 2 groups, and 40k new eligible users arrive per day. How long do you run the test?	600k ÷ 40k = 15 days, rounded up to full weekly cycles: 21 days. Don’t stop early on a significant peek.	chapter-8 scenario
Why randomize an A/B test by user rather than by request?	Each user gets one consistent experience and user-level metrics like retention are attributable. Variance must then also be computed per user.	chapter-8 concept
Why is p(1 − p)/impressions wrong for CTR in a user-randomized test?	Impressions from one user are correlated, so the true variance is larger; the naive formula gives false “significant” results. Use the delta method or bootstrap over users.	chapter-8 concept
What is peeking and why is it harmful?	Repeatedly checking p-values and stopping when significant; it inflates false positives. Use a fixed horizon or sequential testing.	chapter-8 concept
How do you handle network interference in marketplace or social A/B tests?	Cluster randomization (by city or social cluster) or switchback experiments that alternate treatment over time windows.	chapter-8 concept

Interleaving: strength and limitation.	Merges two rankers’ results into one list for the same user; far more sensitive to ranking preference than A/B, but does not measure business metrics.	chapter-8 concept

What must be logged to evaluate a new policy off-policy?	The propensities — the probability with which the old policy showed each item — for inverse propensity scoring.	chapter-8 concept

MoE: what scales with total parameters and what with active parameters?	Memory scales with total (all experts resident); compute per token with active. At large batches, bandwidth per step approaches the full model.	chapter-12 concept

Where do most RAG quality problems originate?	In retrieval — and many retrieval problems are parsing and chunking problems.	chapter-14 concept

Dense retrieval vs BM25: what each misses.	Dense misses exact rare terms (error codes, SKUs, names). BM25 misses paraphrases. Hybrid search uses both.	chapter-14 concept

What is HyDE?	The LLM writes a hypothetical answer, which is embedded and used as the search query, because answers resemble documents more than questions do.	chapter-14 concept

How should RAG treat instructions found inside retrieved documents?	As untrusted data, never as instructions (indirect prompt injection).	chapter-14 concept
What kind of question does GraphRAG help with?	Global “sensemaking” questions across a corpus (main themes across all reports), which chunk retrieval handles poorly.	chapter-14 concept
When does long context beat RAG, and when does RAG win?	Long context (plus prompt caching) suits a small corpus queried rarely. RAG wins for large or changing corpora, permissions, and per-query cost or latency.	chapter-14 concept

RAG debugging: right chunk never retrieved. Fixes?	Parsing, chunking, embedding model, hybrid search, query rewriting.	chapter-14 concept

Working definition of an agent.	An LLM using tools in a loop, directing its own process based on feedback from the environment.	chapter-15 concept
First principle of agent design.	Use the least autonomy that solves the problem: single call → workflow → agent → multi-agent, climbing only when the simpler option fails.	chapter-15 concept
Workflow vs agent.	Workflow: developer-defined code paths — predictable, testable, cheaper. Agent: the LLM decides steps and tools dynamically — flexible, harder to test and bound.	chapter-15 concept
Seven components of an agent.	Model, instructions, tools, context/memory, orchestration loop, environment, guardrails.	chapter-15 concept
Four safety features every agent loop needs.	A step budget, unknown-tool handling, tool errors returned to the model, human approval for consequential actions.	chapter-15 concept
Why prefer task-level tools over thin API wrappers?	Fewer, more capable tools mean fewer steps, and fewer steps mean fewer compounding errors.	chapter-15 concept

Parallelization: sectioning vs voting.	Sectioning splits a task into independent subtasks run at once. Voting runs the same task several times and aggregates.	chapter-15 concept

Evaluator–optimizer pattern.	One LLM generates, another critiques against criteria, looping until good enough.	chapter-15 concept

Most useful kind of evaluator inside an agent loop.	An objective one: tests, compilers, schema validators, constraint checks, simulators — stronger than an LLM judging its own work.	chapter-15 concept
What is “context rot”?	As the context fills with history and tool output, the model becomes slower, costlier and worse at finding what matters.	chapter-15 concept

How do sub-agents help context management?	A sub-task runs in a fresh, clean context and returns only a condensed result.	chapter-15 concept
